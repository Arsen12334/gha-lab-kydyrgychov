                             # Отчёт

1. Workflow — один YAML-файл. Внутри него события (on), внутри jobs — задачи (jobs), внутри каждой job — шаги (steps), а шаг — это команда (run) или готовый action (uses).

2. Job — набор шагов, которые выполняются на одной виртуальной машине, и разные jobs по умолчанию идут параллельно. Step — одно действие внутри job (команда или action), шаги идут по порядку на той же машине.

3. Push запускает workflow автоматически при отправке коммита, а workflow_dispatch — вручную кнопкой Run workflow во вкладке Actions.

4. Через секреты: Settings → Secrets and variables → Actions, потом в workflow ${{ secrets.ИМЯ }}. Значение в логе заменяется на ***, в коде и репозитории его нет.

5. Артефакт — файл, сохранённый после выполнения job. Нужен, чтобы передавать файлы между jobs (каждая job работает на отдельной чистой машине) и чтобы скачать результат сборки.

6. Ключом needs: имя_job. Линтер нужен, потому что он находит ошибки и плохой стиль, не запуская код: тест проверяет только то, что мы догадались проверить, а линтер видит проблемы, которые тестом не покрыты (например, неквотированные переменные).
